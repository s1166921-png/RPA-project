# 跨境仓储物流客户自助查询与 RPA Agent 实施计划书

## 1. 项目目标

建设一个面向客户和运营团队的跨境物流智能服务平台。客户能够自助查询运单、轨迹、重量和账单；运营团队能够通过经过审批的 RPA 工作流，在新智慧系统中完成标识、路由等页面操作。

平台必须满足以下原则：

- 业务数据以新智慧为最终来源，不由 AI 编造。
- 查询和写操作分层：查询优先 API/本地同步库，写操作由受控 RPA Agent 执行。
- AI 仅负责意图识别、参数收集和工作流推荐，不直接决定或执行高风险业务写入。
- 每项写操作都必须有已批准的标准工作流、权限、前置校验、回读校验和审计记录。
- 客户数据按租户隔离；客户只能访问授权范围的数据。

## 2. 范围与阶段

### Phase 0：数据源与安全准备

- 获取新智慧只读 API、服务账号或确认可用的数据同步方式。
- 明确新智慧中允许 RPA 操作的页面、字段、按钮和业务规则。
- 由业务负责人提供并审批每一个写操作工作流。
- 建立测试环境或测试客户、测试运单和回滚规则。

验收条件：完成接口文档、字段映射、账号权限、IP 白名单、测试数据和操作白名单确认。

### Phase 1：客户单号查询 MVP

- 客户输入一个或多个运单号。
- 后端查询新智慧 API 或本地同步库。
- 返回标准化运单状态、物流轨迹、重量、费用摘要和同步时间。
- 支持 Excel 导出和查询历史。

验收条件：真实单号可从新智慧返回，单条查询目标小于 3 秒，批量查询和导出可追溯。

### Phase 2：数据同步与客户门户

- 建立本地业务数据库和增量同步任务。
- 开启客户登录、租户隔离、客户权限和下载权限。
- 提供账单、轨迹、异常筛选和自助导出。

验收条件：客户 A 无法查询或下载客户 B 数据；同步失败有告警；查询页面可显示数据来源及最后同步时间。

### Phase 3：受控 RPA Agent

- 部署独立 RPA Agent，使用专用账号和固定浏览器环境。
- 接入已批准的“增加标识”“移除标识”“更新货物路由”等工作流。
- 支持人工审批、任务队列、失败重试、回读确认和审计。

验收条件：每个工作流在测试环境和真实受控样本中通过完整正向、异常和回滚验证。

### Phase 4：AI 工作流助手

- AI 将自然语言请求转为固定工作流和结构化参数。
- 缺少单号、路由、客户或审批信息时必须追问。
- AI 只能调用授权工具，不能绕过权限、拼接任意接口或直接写入新智慧。

验收条件：AI 对关键金额、状态、重量只引用工具结果；无法识别需求时不执行任何操作。

## 3. 总体架构

```text
客户门户 / 运营后台 / AI 助手
              |
       API Gateway + Auth
              |
         Workflow Engine
          /             \
  Data Service        RPA Orchestrator
      |                     |
API Adapter / Sync       RPA Agent
      |                     |
新智慧 API / 本地库      新智慧网页
      |
PostgreSQL + Redis + Audit Store
```

组件职责：

- 客户门户：单号查询、结果展示、历史记录、导出下载。
- 运营后台：客户映射、工作流版本、审批、同步状态和 RPA 任务管理。
- Workflow Engine：校验输入、权限、状态机、任务步骤、结果和异常处理。
- Data Service：调用新智慧 API、标准化字段、读取缓存和写入同步快照。
- RPA Orchestrator：队列、并发限制、审批门槛、重试、幂等键和任务分发。
- RPA Agent：仅执行白名单工作流中的网页操作，执行后回读确认。
- PostgreSQL：业务索引、轨迹、账单摘要、工作流运行、任务、权限和审计。
- Redis：热门单号缓存、任务锁、限流和短期会话状态。

## 4. 新智慧 API 具体需求

### 4.1 通用要求

- 提供测试环境或专用测试客户与测试运单。
- 使用 API Key、OAuth2 Client Credentials 或服务账号 Token；不使用管理员密码嵌入代码。
- 服务账号只读权限与写权限分离。
- 支持 IP 白名单、HTTPS、请求频率限制、超时规范和错误码文档。
- 提供 OpenAPI/Swagger 文档、字段字典、请求样例和响应样例。
- 所有接口返回唯一业务 ID、最后更新时间、数据来源版本或变更时间。

### 4.2 运单查询 API（V1 必须）

建议能力：

```http
POST /api/shipments/query
```

请求：

```json
{
  "waybillNumbers": ["MO10083353", "MO10083354"],
  "customerCode": "optional-for-service-scope"
}
```

要求：

- 支持单号精确查询和批量查询，单次建议上限 50 条。
- 返回每条单号的 found/not_found/forbidden/source_unavailable 状态。
- 支持分页、排序和按最后更新时间筛选。
- 允许按客户编码或服务账号权限自动限制结果范围。

必需字段：

| 字段 | 用途 |
| --- | --- |
| waybill_number | 运单号，唯一查询主键 |
| customer_code / user_id | 客户归属和租户隔离 |
| customer_order_number / fba_number | 客户识别与业务核对 |
| shipment_status | 当前状态 |
| service | 物流服务/渠道 |
| country | 目的国家 |
| pieces | 件数 |
| actual_weight | 实重 |
| volume_weight | 材积重 |
| charge_weight | 收费重 |
| customs_mode | 报关方式 |
| receivable / currency | 应收及币种 |
| exception_code / exception_reason | 异常信息 |
| created_at / updated_at | 数据追溯与增量同步 |

### 4.3 物流轨迹 API（V1 必须）

```http
GET /api/shipments/{waybillNumber}/tracking
```

必需字段：运单号、节点时间、节点状态、节点描述、发生地、承运商、最后节点标识、轨迹最后更新时间。

要求：轨迹按发生时间排序；状态修正时需提供更新时间或版本号；不可只返回展示文案而没有结构化状态。

### 4.4 增量同步 API（Phase 2 必须）

```http
GET /api/shipments/changes?updated_after=2026-08-03T00:00:00Z&cursor=...
GET /api/tracking-events/changes?updated_after=2026-08-03T00:00:00Z&cursor=...
```

要求：

- 支持 `updated_after` 或 cursor 增量拉取。
- 返回稳定排序和下一页 cursor。
- 支持删除/作废/状态修正事件。
- 支持至少 7 天增量补拉窗口，避免同步任务故障后丢数。
- 最好提供 Webhook，在运单状态或轨迹变化时推送事件。

### 4.5 账单费用 API（Phase 2）

请求维度：客户编码、账期、运单号、费用类型、币种、分页。

必需字段：账单号、账期、运单号、费用类型、金额、币种、税额、应收/已付/未付、费用状态、创建时间、更新时间。

### 4.6 写操作 API（若新智慧提供）

如新智慧能开放以下 API，应优先使用 API 而不是 RPA：

- 新增/移除运单标识。
- 更新货物路由。
- 查询允许的路由字典和状态机。
- 查询操作结果和操作日志。

写接口必须支持：幂等键、操作人标识、审批单号、前置版本号、操作日志和明确错误码。

## 5. 本地数据库与同步设计

建议使用 PostgreSQL 作为主库，Redis 作为缓存和任务协调组件。

核心表：

- `tenants`：客户租户。
- `users`：客户及内部账号。
- `tenant_permissions`：可访问客户编码、店铺和仓库范围。
- `shipments`：运单标准化主数据。
- `tracking_events`：轨迹节点。
- `billing_items`：费用与账单明细。
- `sync_jobs`：同步任务、水位、耗时和失败原因。
- `source_snapshots`：来源系统、请求标识、同步时间和摘要校验值。
- `workflow_definitions`：受控工作流版本与审批要求。
- `workflow_runs`：每次查询或操作的执行记录。
- `rpa_tasks`：RPA 队列、状态、重试次数和幂等键。
- `approval_requests`：人工审批记录。
- `audit_logs`：登录、查询、导出、审批和操作审计。

同步策略：

- 未签收或存在异常的运单：每 5 分钟同步。
- 已签收但 30 天内的运单：每 1 小时同步。
- 历史完成运单：每日同步或按需回查。
- 同步前记录水位；同步成功后才推进水位。
- 每次写库采用 upsert，并保存来源更新时间，避免旧数据覆盖新数据。
- 新智慧不可用时展示最近同步结果和同步时间，不伪造实时数据。

## 6. RPA Agent 设计

### 6.1 执行边界

RPA Agent 默认只读。只有工作流定义中明确列出的页面操作，且请求通过权限与审批后，才允许写入。

禁止项：

- 自由输入任意网页地址或任意脚本。
- 由 AI 自行判断并执行写操作。
- 自动发送企业微信、删除数据、修改费用或批量变更路由，除非对应工作流已单独审批。
- 在日志、截图、前端或 Git 中保存密码、Token、Cookie。

### 6.2 RPA 工作流通用状态机

```text
draft -> pending_approval -> queued -> running -> verifying -> completed
                                      |             |
                                      -> failed <---
                                      -> needs_manual_review
```

每个任务必须包含：

- `workflow_id` 和版本。
- 请求人、租户、运单号、目标值和审批单号。
- 允许执行的账号和页面范围。
- 幂等键，防止重复提交。
- 操作前快照摘要和操作后回读摘要。
- 任务耗时、错误分类、重试次数和人工处理备注。

### 6.3 首批 RPA 工作流

#### A. 增加运单标识

输入：运单号、标识名称、原因、审批单号。

步骤：查询运单 -> 校验归属与当前标识 -> 校验标识在白名单 -> 审批 -> RPA 添加 -> 回读标识 -> 写审计。

失败处理：页面元素变化、运单不存在、标识已存在、权限不足时停止并转人工。

#### B. 移除运单标识

输入：运单号、标识名称、原因、审批单号。

步骤：查询运单 -> 校验标识存在且允许移除 -> 审批 -> RPA 移除 -> 回读确认 -> 写审计。

高风险：涉及财务、异常、锁定类标识时必须二次审批。

#### C. 更新货物路由

输入：运单号、目标路由、变更原因、审批单号。

步骤：查询 -> 校验当前状态允许变更 -> 校验目标路由白名单 -> 审批 -> RPA 更新 -> 回读新路由 -> 写审计。

高风险：批量操作、已出库/已交运状态、跨国家路由必须人工复核。

#### D. 计费重确认（只读模板）

输入：单号列表。

步骤：读取收费重、实重、材积重、应收、服务和报关方式 -> 校验字段完整性 -> 按有费用/无费用模板生成确认内容和 Excel。

本阶段不发送企业微信、不新增或移除标识。

## 7. 客户门户功能

### 7.1 单号查询

- 输入单号、客户单号或 FBA 号。
- 支持换行、英文逗号、中文逗号分隔，单次最多 50 条。
- 返回 found、not_found、forbidden、source_unavailable 四类明确结果。
- 显示数据来源、同步时间、查询时间和必要的业务字段。

### 7.2 批量导出

- 固定 Excel 模板，不由 AI 自由生成关键字段。
- 大批量导出异步执行；导出中心显示排队、运行、完成、失败状态。
- 下载前再次校验租户与文件归属。

### 7.3 AI 助手

- 识别“查轨迹”“查收费重”“查账单”“导出上月账单”“申请改路由”等意图。
- 只产生工具调用建议与结构化参数。
- 缺少单号、月份、目标路由、原因或审批信息时追问。
- 回复中明确标注“系统查询结果”与“操作建议”。

## 8. 功能测试与验收节点

### Node 0：新智慧接口连通性

正向测试：服务账号取得 Token；单号查询 API 对测试单号返回 200 和完整字段；轨迹 API 返回至少一个节点。

异常测试：Token 失效、无权限、限流、超时、未知单号、字段缺失、接口返回 5xx。

通过标准：错误被标准化为明确状态；凭据不出现在日志；失败不写入错误业务数据。

### Node 1：单号查询

正向测试：查询一个真实存在运单，页面字段与新智慧返回一致；查询多个运单，顺序和结果状态正确。

异常测试：空输入、超过 50 条、重复单号、非法字符、未找到单号、上游超时。

通过标准：常规单条查询小于 3 秒；未找到与数据源不可用必须区分；页面不展示内部敏感字段。

### Node 2：同步任务与本地数据库

正向测试：首次全量同步、增量同步、状态更新、轨迹新增、费用修正和断点续跑。

异常测试：中途网络失败、重复事件、旧数据晚到、数据库重启、cursor 失效。

通过标准：数据不重复、不丢失、不用旧版本覆盖新版本；同步状态和水位可查看；失败可重试。

### Node 3：客户隔离与权限

正向测试：客户 A 仅能查询自己的运单、账单、导出和历史；内部运营可按角色查看授权范围。

异常测试：篡改请求中的 customer_id、直接访问其他客户导出 URL、AI 工具调用跨租户、未登录访问。

通过标准：任何跨租户请求返回无权限或无结果；审计记录包含调用人和租户，但不记录密码和原始 Token。

### Node 4：导出

正向测试：单号导出、批量导出、账期导出，列顺序与模板一致，金额、重量和状态与页面一致。

异常测试：空结果、导出任务失败、重复下载、跨租户下载、大文件超时。

通过标准：大文件异步处理；下载需二次鉴权；文件只保留设定期限。

### Node 5：AI 意图与工具控制

正向测试：识别单号查询、轨迹查询、账单查询、计费重确认、改路由申请。

异常测试：缺少参数、模糊请求、诱导 AI 编造金额、诱导 AI 绕过审批、跨客户请求。

通过标准：AI 不在没有工具结果时给出具体状态/金额；高风险请求只创建待审批任务，不直接执行。

### Node 6：RPA 增加/移除标识

正向测试：标准工作流对测试运单添加标识并回读成功；移除后回读不存在。

异常测试：运单不存在、标识已存在、标识不存在、页面元素变化、登录失效、网络中断、审批缺失、重复提交。

通过标准：重复任务不重复写入；失败任务不继续点击；每次写入都有操作前后摘要和审计记录。

### Node 7：RPA 更新路由

正向测试：允许状态下将测试运单更新为白名单目标路由并回读一致。

异常测试：禁止状态、无效路由、已交运运单、批量超限、审批未通过、页面保存失败。

通过标准：路由更新前必须通过状态机校验；保存后必须回读；不可确认时标记 `needs_manual_review`。

### Node 8：性能与可靠性

- 单号缓存命中：P95 小于 1 秒。
- 单号实时回查：P95 小于 3 秒。
- 批量 50 单：异步/并发受控，不能拖垮上游系统。
- RPA Agent：单 Agent 单任务执行；多 Agent 使用队列和资源锁。
- 上游故障：熔断、退避重试、返回最近同步时间，不无限等待。

## 9. 上线准入条件

上线前必须同时满足：

- 新智慧 API 或同步数据源已完成真实样本联调。
- 所有写操作工作流均获得业务书面审批。
- 客户权限隔离、导出权限和审计测试通过。
- RPA 账号为专用账号，权限最小化，密码放入密钥管理系统。
- 完成备份、监控、告警、任务失败通知和人工接管流程。
- 完成至少一轮用户端验收：客户查询、内部审批、RPA 执行、回读确认、日志复查。

## 10. 业务与新智慧对接清单

业务负责人需确认：

- 每个标识的业务含义、可添加条件、可移除条件和审批人。
- 每条路由的适用国家、服务、运单状态和禁止变更条件。
- 费用、收费重和轨迹字段的权威来源及异常处理规则。
- 客户可见字段与内部可见字段清单。

新智慧技术人员需提供：

- API/Swagger、服务账号、测试环境、IP 白名单和限流规范。
- 运单、轨迹、账单、路由和标识字段字典。
- 增量同步或 Webhook 能力。
- 如无写 API，确认 RPA 可操作页面及不可自动化限制。
