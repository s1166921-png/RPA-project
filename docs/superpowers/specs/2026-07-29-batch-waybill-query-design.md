# 批量运单查询与导出设计

## 目标

客户可在现有本地只读门户一次输入多个运单号，查看每条查询状态，并把整批结果导出为一个 Excel 文件。

## 输入与限制

- 输入框升级为多行文本框。
- 支持换行、逗号和空格分隔单号。
- 去除空项并按首次出现顺序去重。
- 每批最多 50 个有效单号；超过时不执行查询，并明确提示。

## 接口与查询流程

- 新增 `POST /api/shipments/batch-lookup`，请求体为 `{ "waybillNumbers": ["..."] }`。
- 后端从请求中规范化单号后，逐条调用既有只读 `lookupWaybill` 服务。
- 每条保留独立状态：`found`、`not_found`、`source_unavailable` 或 `invalid_input`。
- 单条上游失败不会中断同批其他单号；接口返回 HTTP 200 和整批结构化结果。

## 页面行为

- 提交后显示“正在查询 N 个单号”。
- 结果表保留输入顺序，展示单号、状态和必要摘要；不显示失败单的虚构业务数据。
- 查询完成后提供“下载本批 Excel”按钮。
- 空输入、超过 50 条、直接以 `file://` 打开页面保持明确提示。

## Excel 输出

- 查询成功的行沿用现有固定字段顺序。
- 表格增加 `查询状态` 与 `失败原因` 列。
- 未找到、数据源不可用和无效输入仍占一行，业务字段留空，便于客户核对补查。

## 安全与可靠性

- 仅复用新智慧只读适配器，不增加写入、标签、导出新智慧原始数据等操作。
- 本地原型服务继续默认监听 `127.0.0.1`。
- V1 不引入客户登录；租户隔离仍属于后续节点，当前功能只在本机受控验证环境使用。

## 验收

1. 用户粘贴两个真实单号后，页面显示两条成功结果。
2. 混合有效单号、空项和不存在单号时，页面完成整批并准确标记状态。
3. 下载的 Excel 同时包含成功和失败行，字段顺序稳定。
4. 超过 50 个有效单号时，页面与接口均拒绝执行。
