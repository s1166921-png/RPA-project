# 新智慧 MPAPI 企业查询系统实施计划

## 1. 目标与边界

建设内部运营查询系统：员工输入一个或多个运单号，选择货物信息、物流轨迹、费用或导出需求，系统通过新智慧 MPAPI 返回标准化结果和 Excel。V1 仅调用只读接口；任何新增路由、删除路由、设置派送等写操作进入 V2，必须经过审批、预览、幂等校验和审计。

不把企业 MPAPI Key 交给浏览器、客户或 AI。Key 仅保存为服务端 Secret；所有页面调用本系统后端，再由后端调用新智慧。

## 2. 已确认的 MPAPI 能力

| 业务能力 | 接口 | V1 使用方式 |
| --- | --- | --- |
| 运单列表/按时间同步 | `POST /mpapi/v5/shipment/list` | 按 `shipment_id`、`waybill_id`、`user_number`、创建/揽货/更新时间分页查询；每页最多 100 条。 |
| 运单详情 | `POST /mpapi/v5/shipment/info` | 按系统运单号或末端跟踪号读取货物、地址、重量、服务和状态。 |
| 单票路由 | `POST /mpapi/v5/shipment/tracking` | 返回当前状态、承运商、跟踪号、轨迹节点。 |
| 批量路由 | `POST /mpapi/v5/shipment/batch_tracking` | 单次最多 30 条；用于批量轨迹查询。 |
| 客户/用户清单 | `POST /mpapi/v5/user/list` | 仅内部配置客户映射和核对 `user_number`；不在客户前台展示敏感资料。 |
| 写入接口 | `shipment/add_tracking`、`shipment/delete_tracking` 等 | V1 禁用；V2 走审批工作流。 |

所有调用使用 `Authorization: Bearer <MPAPI_KEY>`、`Content-Type: application/json`、`Accept: application/json`。MPAPI Key 必须由新智慧为企业/员工账号创建；普通客户 API Key 不能替代。

## 3. V1 产品流程

```mermaid
flowchart LR
  A[员工输入单号] --> B[选择查询需求]
  B --> C[后端权限与限流]
  C --> D[MPAPI 适配器]
  D --> E[详情/路由/列表接口]
  E --> F[字段标准化与校验]
  F --> G[页面结果或 Excel]
  F --> H[审计日志与来源快照]
```

页面首屏保持简单：查询内容下拉框、单号输入框、查询按钮、结果列表和 Excel 导出。AI 助手作为补充入口，只识别意图和参数，再调用相同的受控后端工具；它不直接回答状态、金额或重量。

## 4. 字段标准

### 货物信息

输出字段：系统运单号、客户单号、客户编号 `user_number`、服务代码/名称、目的国、收件人、件数、实重、材重、收费重、固定/销售收费重、FBA 号、末端承运商和跟踪号、运单状态、创建/揽货/发货/签收时间、数据来源、查询时间、快照 ID。

默认不展示内部备注、员工编号、成本、利润、完整收件地址和联系方式；这些字段仅可由内部管理员按角色开关查看。

### 物流轨迹

输出字段：运单号、状态、承运商、跟踪号、节点时间、节点内容、节点备注、来源和查询时间。批量查询按输入顺序返回，找不到、上游失败与成功结果必须逐条区分。

## 5. 实施里程碑与验收

### M0: 企业授权与安全基线

1. 业务方创建企业 MPAPI Key，并确认该 Key 可读取目标三张单。
2. 在部署环境的 Secret 中配置 `MPAPI_ENTERPRISE_TOKEN`，不写入 `.env.example`、Git、日志或前端。
3. 启用内部登录、管理员角色、请求限流和审计。

验收：未携带 Key 的调用失败；页面、导出文件和日志中均无法检索到 Key；未登录用户无法调用企业查询接口。

### M1: MPAPI 只读适配器

1. 新建 `new-wisdom-mpapi-provider`，与现有客户 API 适配器分离。
2. 实现 `findByWaybill`：先 `shipment/list` 以 `shipment_id`/`waybill_id` 解析，再 `shipment/info` 与 `shipment/tracking` 补全详情和轨迹。
3. 实现 `findByTimeRange`：按 `updated_start_time/updated_end_time` 分页同步，检查页大小上限 100。
4. 实现批量路由：每批最多 30 条，超出自动分批并按原输入顺序合并。

验收：使用企业 Key 查询 `MO10084770`、`MOY2608044753`、`MO10084768`；页面的关键字段与新智慧页面逐条一致。运单不存在、上游超时、部分成功均有明确结果。

### M2: 查询工作流与导出

1. 货物信息工作流调用 MPAPI 详情接口。
2. 物流轨迹工作流调用 MPAPI 单票/批量路由接口。
3. 批量 Excel 固定字段顺序，记录查询条件、来源和快照 ID。
4. 时间范围查询支持按创建、揽货和更新时间获取单号，再进入详情/导出。

验收：单票目标响应 1-3 秒；30 条路由批量查询成功；50 条导出为异步任务；Excel 字段与页面字段一致。

### M3: 数据缓存与可靠性

1. 近期轨迹短缓存，历史详情/账单长缓存；结果展示同步时间。
2. 增量同步任务按更新时间拉取并保存原始响应快照。
3. 上游失败返回上次成功同步时间，任务可重试，不阻塞门户。

验收：缓存命中不调用上游；缓存过期仅刷新目标单号；重复请求不产生重复导出或重复审计数据。

### M4: 受控写入操作

1. 新增/删除路由、派送设置等操作只允许定义好的工作流调用。
2. 每次写入先显示差异预览，要求人工审批并记录审批人、请求体摘要和新智慧返回结果。
3. 幂等键防止重复提交；写入后自动回读详情/轨迹确认结果。

验收：无审批令牌的写入一律拒绝；重复提交不会重复新增路由；审计可完整追溯操作者、时间、目标和结果。

## 6. 测试矩阵

| 场景 | 测试结果 |
| --- | --- |
| 单号存在 | 详情、重量、状态和轨迹与新智慧一致。 |
| 单号不存在 | 返回 `not_found`，不伪造数据。 |
| `shipment_id`/`waybill_id`/客户单号 | 可按文档支持的标识正确解析。 |
| 批量查询 | 输入顺序保留；单条失败不影响其他单号。 |
| 时间查询 | 边界时间、分页、最多 100 条/页均正确。 |
| 批量路由 | 自动按 30 条切分并合并。 |
| 安全 | Key 不泄漏；匿名/非授权访问被拒绝；客户模式按租户隔离。 |
| 写入接口 | V1 无法调用；V2 缺少审批、预览或幂等键时被拒绝。 |

## 7. 上线门槛

上线前必须满足：企业 MPAPI Key 联调成功；三张真实运单验收通过；源数据字段映射确认；安全测试通过；内部管理员账号创建完成；备份、监控、错误告警和 Key 轮换流程已启用。
