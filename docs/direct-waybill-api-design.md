# 单号直查 API 设计

## 目标

第一阶段提供无需登录的单号直查页面。客户输入运单号后，系统通过新智慧的受认证接口返回标准化的运单信息；不发送消息、不导出文件、不修改新智慧任何数据。

## 已验证事实

- 新智慧运单页受登录会话保护。
- 运单列表的真实后端接口为 `POST /rest/tms/csos/shipment/lists`。
- 接口使用 JSON 请求体，单号筛选字段为 `waybill_number`；页面还提供 `keywords` 和 `lading_number`。
- 成功响应采用页面状态容器结构，运单行位于 `data.components.gridView.table.dataSource`。
- 默认页签为 `ready`，单号直查服务不得依赖某个页面页签；适配器应显式提供查询范围并以接口响应为准。

## 架构

```text
浏览器单号输入
  -> 直查 API
  -> 查询工作流
  -> 新智慧 API 适配器
  -> POST /rest/tms/csos/shipment/lists
  -> 字段标准化
  -> 客户查询结果
```

前端不保存新智慧账号、密码、Cookie 或原始响应。后端持有只读服务账号的受保护凭据，建立短生命周期会话，调用接口后只返回允许展示的标准字段。RPA 只在 API 不可用、字段缺失或接口权限变化时作为只读备用适配器。

## 查询协议

内部接口为 `POST /api/shipments/lookup`，请求体只包含：

```json
{ "waybillNumber": "MO10083334" }
```

返回字段包括：运单号、FBA 号、当前状态、服务、目的国家、收件人、件数、实重、材重、收费重、报关方式、应收费用、最后路由、来源、查询时间和快照编号。

当新智慧没有数据、接口超时或返回结构变化时，页面展示明确状态，不猜测物流轨迹、重量或金额。

## 凭据和安全边界

- 新智慧账号只在服务端环境变量或密钥管理系统中保存，绝不放入浏览器 JavaScript、Git 或日志。
- 所有新智慧操作为只读：禁止企业微信发送、标识增删、运单编辑和导出。
- 查询日志只保存单号掩码、耗时、结果状态与快照 ID；不保存新智慧会话 Cookie。
- 当前阶段未做客户登录和租户隔离。第二阶段在同一个工作流入口前增加登录身份与运单归属校验，不改变 API 适配器。

## 验收与测试

- 输入有效单号时，页面展示来自适配器的结构化数据和来源时间。
- 空单号不发起请求并提示补充单号。
- 新智慧无记录时显示“未找到该单号”，不泄漏其他记录。
- API 超时、未认证和返回结构异常均显示可理解的错误，并记录安全的审计事件。
- 自动化测试使用本地 API 模拟器，不调用新智慧生产环境。
